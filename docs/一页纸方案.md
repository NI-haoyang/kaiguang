## 一句话

新笔记本到手，先别急着装软件：**先验这台机器是不是真的全新，再看清它里面已经装了什么**——「开机第一天」读一份只读体检报告，给出一张按「今天 / 这周 / 以后」排好的开荒单，和一份**默认全部注释、需要你自己逐条确认**的脚本。

## 要解决的真问题

新笔记本出厂就带着厂商全家桶：一台天选身上有 14 个华硕组件、3 套安全软件、4 个浏览器、5 个视频音乐客户端、23 个第三方自启服务。新生不知道哪些是必需的、哪些是重复的、哪些删了会出事。网上的「新电脑必装清单」有两个毛病：**不知道你的电脑里已经有什么**，以及**上来就给一串要你复制粘贴的命令**。

## 它怎么做（四步，全程在本地）

0. **先验机**：电池设计容量 vs 满充容量、循环次数、系统安装天数、安全启动 / TPM / 激活状态、缺驱动的设备、屏幕分辨率与刷新率。判断「是不是全新机」靠的不是外观，是这几个数字。再加一个全屏纯色页，用眼睛查坏点和漏光——这一步没法自动化，也不该假装能。

1. **只读采集**：`collect.ps1` 读系统信息、磁盘、已装软件（注册表 Uninstall 键，不碰 Win32_Product）、启动项、第三方自启服务、Defender 与防火墙状态，输出一份 `report.json`。不写注册表、不装东西、不联网。
2. **看得懂的解释**：规则库把「一堆陌生名字」翻成人话——不只是「装了 3 套安全软件」，而是「Defender 显示关闭是正常的，装了第三方杀软它会让位，不是中毒」。
3. **可审阅的开荒单**：按档位（学习办公 / 游戏 / 只看看）生成三阶段清单和脚本。脚本每一行都带 `#`，你确认哪条要执行，才手动删掉井号。

## 和现成工具的区别

| | Ninite / winget | WinUtil 这类优化脚本 | 开机第一天 |
|---|---|---|---|
| 起点 | 从零装 | 一键改系统 | **先看你已经有什么** |
| 输出 | 装什么 | 直接执行 | 清单 + **需要你确认**的脚本 |
| 解释 | 无 | 少量 | 每条都说「为什么」和「删了会怎样」 |

核心主张：**不替你改系统，只替你搞明白。** 这是安全边界，也是这个作品的态度。

## 演示（30 秒能看完）

1. 现场跑一次 `collect.ps1`（3 秒），把 `report.json` 拖进网页。
2. 页面给出开荒指数和体检报告：先看到「3 套安全软件在互相扫」「防火墙关着」。
3. 切一下档位，开荒单从「卸载」变成「只关自启」。
4. 打开可审阅脚本：**全是注释**，一行行有解释。

## 11.28 当天要做的增量

骨架已经能跑（采集 + 规则 + 开荒单 + 脚本）。当天做的是**让它更像一个会解释的人**：

- [ ] 接 LLM：把 `report.json` 和规则结论交给模型，生成「先做哪一件」的自然语言建议（接口已留，`server.mjs` 的 `/api/analyze`）。
- [ ] 加「为什么这条不建议动」的反向解释，避免新手误删运行库。
- [ ] 现场找 2–3 位同学的真机跑一遍，把真实案例放进页面（这是最好的答辩素材）。
- [ ] 加一个「改完前后对比」：再跑一次采集，并排显示自启数量变化。
- [ ] 验机自测页：键盘逐键、摄像头/麦克风、接口通断——把「人眼看」的部分做成引导。

## 风险与边界

- 只读：采集脚本不含任何写入动作，页面上明示。
- 不静默：脚本全部注释，不提供「一键执行」。
- 不上传：默认纯本地；只有主动点「AI 深读」才会发请求。
- 不评价人品：分数只描述「这台机器还需要多少整理」，不写「你的电脑很危险」。
